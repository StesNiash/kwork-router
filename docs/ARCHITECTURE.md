# Архитектура kwork-router

## Роль

`kwork-router` — витрина, а не монолит. Он не содержит бизнес-логики парсеров и ботов.
Его задача: показать семейства услуг, их статус и ссылки на отдельные репозитории.

## Слои

```text
kwork-router/
├── index.html          # статическая витрина
├── styles.css          # оформление
├── app.js              # только фильтр карточек
├── data/services.json  # реестр семейств
├── docs/               # решения и границы
├── tests/              # проверка реестра и HTML
└── KWORK.md            # что можно обещать покупателю
```

## Почему без фреймворка

- Нет сборки и `node_modules`.
- Работает с GitHub Pages и из локального файла.
- Легко проверить: HTML + JSON + один тест.
- Витрина не должна требовать инфраструктуры, которую сама же продаёт.

## Связь с семействами

```text
kwork-router (витрина)
   ├── kwork-hermes-vps     active   → установка Hermes
   ├── kwork-parser         planned  → парсеры и выгрузки
   ├── kwork-tg-bot         planned  → Telegram-боты
   ├── kwork-sheets         planned  → Google Sheets / Apps Script
   ├── kwork-python-scripts planned  → небольшие утилиты
   ├── kwork-monitor        planned  → мониторинг и уведомления
   ├── kwork-api-sync       planned  → API-синхронизация
   └── kwork-ai-rag         planned  → RAG/ассистенты
```

Один репозиторий может обслуживать несколько карточек. Например, `kwork-tg-bot` — заявки, FAQ и оплату.
Но витрина не дублирует их код: только статус и ссылку.

## Контракт данных

Каждое семейство в `data/services.json` обязано иметь:

- `id` — стабильный идентификатор;
- `number` — номер карточки в реестре;
- `title`, `summary`;
- `repo` — имя отдельного репозитория;
- `status` — `active` или `planned`;
- `wave` — очередь публикации;
- `price_from`, `term`;
- `bullets`, `demo`, `tone`.

Тест проверяет уникальность `id` и `number`, допустимые статусы и наличие всех полей.

## Границы

- Витрина не хранит токены, клиентские данные и ключи.
- `planned` не значит «готово»: ссылка на демо появляется только после тестов.
- Цены в JSON — черновые, для карточки и брифа.
